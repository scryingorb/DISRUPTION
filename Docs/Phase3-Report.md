## CRUSH architecture and exact DAMAGE mapping

Signal flow: driven input -> symmetric ADC range +/-1 -> shared sample-and-hold clock / independent held channel values -> blended adjacent bit-depth quantizers -> mode crossfade -> reserved global stages -> MIX/OUTPUT/final DC protection.

For d = smoothed DAMAGE/100 in [0,1]:

```
nominalBits = 16 - 13*d^0.85
requestedCaptureHz = 96000 * exp(log(600/96000)*d^1.4)
effectiveCaptureHz = min(actualProcessingSampleRate, requestedCaptureHz)
```

| DAMAGE | Effective bit depth | Requested capture frequency |
|---|---:|---:|
| 0% | 16.000 | 96,000 Hz (capped to native rate) |
| 20% | 12.690 | 56,325 Hz |
| 50% | 8.788 | 14,030 Hz |
| 75% | 5.820 | 3,228 Hz |
| 90% | 4.114 | 1,203 Hz |
| 100% | 3.000 | 600 Hz |

Low DAMAGE mainly reduces resolution gently; middle settings remove high-frequency sampling information and expose quantization; high settings become heavily held, stepped and aliased. The power/exponential mappings are continuous, not fixed skip-counts. Requested frequencies and bit depths depend on DAMAGE, while actual sample capture intervals are derived from the host rate. At low DAMAGE, a requested rate above the host rate simply captures every frame.

Clock mechanics: beginFrame is called exactly once per processing frame before either channel. The first frame captures immediately. Later frames add effectiveCaptureHz/sampleRate to a shared double phase accumulator; crossing one triggers a capture and subtracts one. The clock never resets merely because DAMAGE or MODE changes. Noninteger hold lengths alternate between adjacent frame counts. At DAMAGE=100, holds are 73/74 frames at 44.1 kHz, 80 at 48 kHz, 147 at 88.2 kHz and 160 at 96 kHz: all represent 600 Hz. Measured capture counts agree with requested physical rates within one event over a second.

Stereo shares this timing/capture flag, but stores two independent sample values. Capturing the left channel never substitutes its value into the right. CRUSH keeps running while inactive so selecting it does not restart the clock or reuse stale input. Tests also prove stereo equals two identically-clocked mono engines and output is invariant to callback partitions of 1, 17, 128 and 511 frames at every required rate.

Quantization uses a signed-style symmetric grid with inclusive +/-1 rails:

```
b = nominalBits
n = floor(b)
fraction = b - n
levelsLow = 2^(n-1)
levelsHigh = n < 16 ? 2*levelsLow : levelsLow
qLow = round(heldInput*levelsLow)/levelsLow
qHigh = round(heldInput*levelsHigh)/levelsHigh
output = (1-fraction)*qLow + fraction*qHigh
```

The input is clamped to the representable ADC range before capture, an intentional part of digital overload behavior. No global limiter was added. At 100% DAMAGE the step is 0.25; including both symmetric rails gives nine distinct values from -1 to +1. The nominal bit count describes grid resolution rather than a packed integer PCM encoder.

Quantization is reapplied to the held input using the current smoothed coefficients. Interpolating neighboring fixed grids prevents parameter-driven grid jumps on a constant input, while input-dependent quantization steps and hold edges remain intact. There is no dither, RNG or reconstruction smoothing. Levels are bounded away from zero, so invalid/divide-by-zero quantization is excluded. Non-finite DAMAGE falls back to zero; invalid input is sanitized. Extreme quiet signals can quantize to silence, especially at three-bit resolution; this is intentional digital degradation, not a reason to add automatic normalization.

DRIVE changes ADC input level and overload; DAMAGE changes grid resolution and capture rate. The global parameter id `crush` still routes only to the unchanged placeholder CrushProcessor. It has no audible effect in any mode in this phase. CRUSH mode is selected by `mode=3` and controlled by DRIVE/DAMAGE.

## CHAOS architecture and exact DAMAGE mapping

Signal flow: soft input preconditioning -> biased repeated triangle reflection -> blend with conditioned input -> biased saturation/soft bounding -> dedicated 5 Hz DC blocker -> mode crossfade and existing global chain.

For d = smoothed DAMAGE/100:

```
conditioned = x / sqrt(1 + (x/12)^2)
threshold = 1.65 * exp(log(0.16/1.65)*d^0.85)
foldAmount = 0.04 + 0.96*d^0.8
foldBias = 0.03 + 0.30*d*d
shapeBias = 0.025 + 0.22*d*d
intensity = 1/0.85 + 1.5*d
compensation = 1/(1 + 0.35*d*d)

fold(v,t) = t - abs(remainder(v-t, 4*t))
offset = foldBias*threshold
folded = 0.8*(fold(conditioned+offset,threshold)-fold(offset,threshold))/threshold
mixed = (1-foldAmount)*conditioned + foldAmount*folded
centre = tanh(shapeBias)
output = (0.85*compensation)/(1-centre*centre)
         * (tanh(intensity*mixed + shapeBias)-centre)
```

Preconditioning has unity small-signal slope, while limiting arbitrary input to +/-12 before the wavefolder. This prevents overload from sweeping millions of folds during DAMAGE automation. Reflection returns a value in [-threshold,+threshold] without an iterative fold loop; runtime does not increase with input amplitude. The threshold falls from 1.65 to 0.16, while the folded-path share grows from 4% to 100%, creating increasingly repeated fold reversals instead of flattened peaks.

The 0.8 normalization gives the folded path useful output amplitude even as its threshold shrinks. A bias shifts positive/negative fold positions; subtracting the zero-input fold guarantees silence remains zero. The post-fold biased tanh adds unequal compression and bounds output smoothly; it is one purposeful saturator, not arbitrary nonlinear stacking or a brick-wall limiter. Bias subtraction also ensures zero input remains zero. There are no random processes. Cached per-frame coefficients (including the zero-input fold) avoid recomputing mappings separately for both channels or recomputing the reference fold for every sample.

Low DAMAGE retains mostly conditioned input with subtle nonlinear coloration. Middle settings introduce clear fold reversals and unequal harmonic structure. High DAMAGE sends essentially the whole signal through many reflected cycles and asymmetric saturation. Internal compensation keeps that increased density from being represented mainly as increased level. Tests verify repeated slope reversals, continuity at fine transfer-curve spacing, asymmetry, mathematical bounds even at double extremes, deterministic rendering and meaningful differences between DRIVE=36/DAMAGE=20, DRIVE=12/DAMAGE=90 and DRIVE=36/DAMAGE=100.

## DC protection, smoothing and switching

CHAOS uses the same topology as RIP through a new reusable DCBlocker helper: independent double-precision histories, 5 Hz corner, coefficient r=exp(-2*pi*5/processingSampleRate), gain g=(1+r)/2, and y[n]=g*(x[n]-x[n-1])+r*y[n-1]. History below 1e-24 is flushed to zero. The existing final DC blocker remains. CHAOS therefore has two five-Hz blockers at fully wet settings, like RIP (about 0.24 dB total attenuation at 30 Hz). Its filter history keeps running even while inactive to avoid a stale DC burst when selected. CRUSH is symmetric and relies on the existing final DC protection.

Existing smoothing is unchanged:

- DAMAGE: 10 ms, feeding continuous bit/rate/fold/asymmetry mappings.
- MODE: 5 ms complementary weight ramps; repeated changes retarget current weights.
- DRIVE/MIX/OUTPUT/BYPASS: 20 ms.
- Final DC correction engagement: existing 20 ms fade at the fully dry endpoint.

All weights/coefficients advance once per frame and are shared across channels. Stateful RIP, CRUSH and CHAOS stay warm; BURN/BREAK are evaluated when weighted into the output. No mode-switch object creation, heap buffer, lock, file operation, logging or exception is introduced in the callback. Denormal suppression and finite-input/emergency protection remain.

No algorithmic buffer latency was introduced; reported latency remains zero. CRUSH's changing signal is inherently held for up to about 1.67 ms at 600 Hz. That is its time-varying digital effect, not an extra constant delay added for switching. If its initial captured sample is zero, a short initial block can remain zero until the next capture; host tests check a complete capture window rather than incorrectly requiring every block to contain audio.

## Compensation and five-mode level comparison

- BURN and BREAK: existing gain design, unchanged.
- RIP: existing fixed 1.12 (+0.984 dB), unchanged.
- CRUSH: unity output gain; no makeup normalization.
- CHAOS: 0.85 saturation scale with reciprocal low-DAMAGE intensity to retain approximately unity small-signal gain; 0.8 folded-path normalization; bias-slope denominator; new compensation 1/(1+0.35*d^2), unity at 0% and 0.740741 (-2.607 dB) at 100%. This trims high-DAMAGE density conservatively instead of chasing exact RMS.

A first level pass showed a 7.807 dB representative spread, led by low-DRIVE/high-DAMAGE CHAOS. The compensation reduced the final worst spread to 5.98319 dB across eighteen multisine combinations (amplitude 0.5/1, DRIVE 0/12/36, DAMAGE 0/50/100). Most strongly driven comparisons are closer. This is a steady-state RMS measurement, not perceptual loudness certification; transient crest factors and timbres remain different. Coarse CRUSH can mute below-grid signals, so no claim is made that every possible quiet source has equal mode levels.

The common listening-source setting DRIVE=12/DAMAGE=65 produces raw RMS values BURN 0.506508, BREAK 0.545114, RIP 0.491826, CRUSH 0.601849 and CHAOS 0.403387 (about 3.48 dB max spread). No detector-based normalization or end-of-chain brick-wall limiter was introduced.

## Aliasing and future HQ

CRUSH intentionally aliases when sampling below the source's bandwidth. At DAMAGE=100, a 437 Hz input sampled at 600 Hz folds to 163 Hz. Its measured aliased amplitude is about 0.702 at all four host rates, directly demonstrating similar physical intent across them. Fractional hold lengths introduce host-grid timing jitter; no reconstruction filter attempts to hide this digital texture.

CHAOS generates substantial above-Nyquist harmonics from repeated reflection, asymmetry and saturation. With input amplitude 0.8, DAMAGE=75 and input frequency 0.21*sampleRate, the measured folded component at 0.37*sampleRate is about 0.504. These spectral bins can contain multiple folded harmonics; they are evidence of unresolved aliasing, not isolated third-harmonic estimates. Existing BURN/BREAK/RIP alias measurements still apply. HQ is inactive; no anti-alias or oversampling system was added.

The per-frame engine hook keeps clocks separate from per-channel values and allows future oversampling to advance state at the actual processing rate. CRUSH's physical target frequencies must remain in Hz, and CHAOS/RIP DC blockers must be prepared at their actual processing rate if moved inside an oversampled region. Preserving intentional CRUSH fold-back while improving analog/fold-engine aliasing needs an explicit future design decision.
